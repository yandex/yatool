# Переменные сборки

`buildvars::TBuildVars` из `libs/buildvars` хранит карту имён и значений. Для значений используются [типы и кодек библиотеки secret](../secret/README.md).

## Карта переменных

`TBuildVars::Load(json)` заменяет карту из JSON-объекта «имя → строка или число», декодируя каждое значение в `TData` или `TSecret`. При ошибке прежняя карта сохраняется. `Find(name)` возвращает указатель на значение либо `nullptr`; указатель действителен до следующей успешной загрузки или уничтожения карты. Имена хранятся буквально, поиск регистрозависимый.

`Add(name, value)` добавляет типизированное значение без декодирования; повторное имя вызывает ошибку без замены. `GetValues()` даёт доступ только для чтения. Порядок обхода не определён.

JSON-число преобразуется в строку внутри `TData`; секретное число задаётся строкой, например `"secret:123"`. Целые числа сохраняются точно, дробные — без дополнительного округления сохранённого `double`; `null`, логические значения, массивы, объекты, NaN и бесконечности запрещены. Исходное написание числа (например, ведущие нули) восстанавливать нельзя — для него нужна строка.

```cpp
buildvars::TBuildVars variables;
variables.Load(NJson::TJsonMap{{"MODE", "release"}, {"TOKEN", "secret:base64:auth/token:dmFsdWU="}});
const auto* token = variables.Find("TOKEN");
```

Карта хранит значения; подстановку выполняет `runevar` через адаптер исполнителя.

## Подключение к Larry

`runevar` за один проход строит строки для исполнения и диагностики. Адаптер `cmd_executor` раскрывает inline-секрет только для процесса; в диагностике подставляет `***`. Для именованного значения оба представления содержат полный путь. Workspace удаляет созданные файлы после исполнения, ошибки или отмены, в том числе при сохранении build-root. Ранее существовавшие файлы ему не принадлежат.

Sandbox-токен проходит через протокол, граф и Fetcher как `TSecret`; переменная `SANDBOX_TOKEN` доступна командам через общий путь подстановки. Старое поле токена читается буквально, без разбора префиксов. `token_redaction::Redact` остаётся для ошибок внешнего загрузчика, которые уже могут содержать токен как обычный текст. Вывод самой дочерней программы не фильтруется.

VCS использует общий декодер в режиме `Vcs`, материализацию `TData` и прежнее владение каталогом ресурса. Карта имён ему не нужна.

## Передача карты

Тип заголовка остаётся `start_build`. Поле `version: 2` выбирает формат с обязательным JSON-объектом `build_variables`: имя → закодированная строка или число. Пустой объект допустим. Отсутствие версии или целая версия `1` выбирает прежний формат без карты; другие версии и неверные типы отклоняются. Затем передаётся прежний JSON графа; карта в него не входит.

`BUILD_ROOT`, `SOURCE_ROOT`, `TOOL_ROOT` и `RESOURCE_ROOT` задаёт Larry. Клиентская карта не может переопределять эти имена или имена ресурсов `conf`; конфликт отклоняется до запуска сборки. Каждая сборка владеет своей картой, в том числе в режиме демона.

В v2 новый сервер берёт Sandbox-токен из inline-секрета `build_variables.SANDBOX_TOKEN`, например `"secret:token"`. Одно значение используется Fetcher и подстановкой в команды; отсутствие переменной означает отсутствие авторизации. До внедрения версии поле `sandbox_token` сохраняется в обоих форматах: в v2 отправитель записывает туда те же буквальные байты токена, что находятся в карте. Старый сервер принимает такой запрос, использует это поле и игнорирует карту; новый сервер в v2 использует карту и игнорирует поле. Удаление дублирующего поля отложено до внедрения серверов с поддержкой версии.

`ya` передаёт `SHALLOW_ROOT`, заданный `FREPKAGE_ROOT` и снимки `YA_TOKEN_PATH`/`DOCKER_CONFIG_PATH`, если они доступны по правилам текущего раннера. Содержимое исходных файлов считывается до отправки запроса; Larry создаёт свои копии в workspace. Sandbox-токен передаётся отдельно от YA OAuth как `SANDBOX_TOKEN` в той же карте; эти учётные данные могут различаться.

В Python-клиенте аргумент `build_variables=None` сохраняет v1, переданный словарь (в том числе `{}`) выбирает v2. Функции `_native.encode_data(bytes, relative_path=None)` и `_native.encode_secret(bytes, relative_path=None)` используют общий кодек. Например, `_native.encode_secret(b'token', '.larry-variables/ya_token')` задаёт секретный файл. После отказа сервера клиент не повторяет запрос как v1.

Аргумент Python API `sandbox_token` сохраняет совместимость: в v1 он заполняет старое поле, а в v2 — отсутствующий `SANDBOX_TOKEN` в карте. Явно заданная переменная имеет приоритет; исходный словарь не меняется. В v2 эффективный токен также записывается буквально в поле `sandbox_token` для старого сервера.
