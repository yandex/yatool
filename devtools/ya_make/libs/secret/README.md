# Данные и секреты

`libs/secret` содержит типы значений и общий кодек. Библиотека не зависит от JSON, графа или `runevar`.

`secrets::TData` хранит обычные данные, `secrets::TSecret` — секретные. Оба типа владеют байтами и необязательным относительным именем файла. Общая реализация находится в `detail`; преобразования секрета в `TData` нет.

## Кодирование

`secrets::DecodeString` возвращает `std::variant<TData, TSecret>`. Префиксы регистрозависимы: сначала необязательный `secret:`, затем необязательный `base64:`. После `base64:` первое двоеточие отделяет имя файла от содержимого; без него значение остаётся строкой. Декодированные байты повторно не разбираются.

| Вход | Результат |
| --- | --- |
| `text` | `TData` со строкой `text` |
| `base64:dmFsdWU=` | `TData` со строкой `value` |
| `base64:some/path/vcs.json:dmFsdWU=` | `TData`: байты `value`, имя `some/path/vcs.json` |
| `secret:value` | `TSecret` без имени файла |
| `secret:base64:auth/token:dmFsdWU=` | `TSecret`: байты `value`, имя `auth/token` |

`secret:base64:dmFsdWU=` задаёт секрет без имени файла. Пустое содержимое допустимо, пустое имя между двоеточиями — ошибка. Имена относительные, разделитель каталогов — `/`; абсолютные пути, компоненты `.` и `..`, обратная косая черта, двоеточия и управляющие символы запрещены. Base64 использует стандартный алфавит и padding `=`. Неизвестные префиксы остаются текстом.

Обратное преобразование: `EncodeBase64(string_view)` для строки, `EncodeData(TData)` и `EncodeSecret(TSecret)` для типизированных значений. Все три используют Base64; два последних сохраняют имя файла. Эти функции также позволяют сохранить буквальное содержимое, начинающееся с префикса. Base64 не шифрует данные: результат кодирования секрета нельзя выводить в лог.

Режим `DecodeString(value, EDecodeMode::Vcs)` использует тот же разбор, но принимает только ссылку `sbr:<id>` либо Base64 с именем файла и непустым содержимым. Ссылка возвращается в `TData` без имени файла для загрузчика; размер Base64 ограничен 16 МиБ. Режим по умолчанию — `Variables` — поддерживает все формы из таблицы.

## Доступ и вывод

У `TData` байты доступны через `GetValue()`, у `TSecret` — через явный `GetSecret()`; оба возвращают заимствованный view и недоступны на временном объекте. `GetRelativePath()` возвращает имя, пустой путь означает строку. Секрет сравнивается только с другим секретом, по байтам.

fmt, spdlog и потоки выводят для секрета `***`; обычные данные выводятся открыто. Хранилище секрета затирает свой буфер при освобождении. Исключение из core dump поддерживается на Linux; на macOS и Windows оно не реализовано. Явное раскрытие, кодирование и внешние библиотеки могут создавать обычные копии байтов.

## Материализация

`Materialize(buildRoot)` возвращает `std::variant<std::string, std::filesystem::path>`: байты без файловых операций, если имя пустое, либо полный путь `buildRoot / имя`. Во втором случае `buildRoot` должен существовать и быть абсолютным; недостающие вложенные каталоги создаются. Существующий файл с теми же байтами используется повторно; отличающееся содержимое вызывает ошибку без перезаписи. На Linux/macOS переходы через симлинки запрещены; для повторного использования файл должен быть обычным и недоступным группе и остальным пользователям. Новые файлы имеют права `0600`, каталоги — `0700`.

На Linux/macOS запись идёт во временный файл в том же каталоге, готовый файл атомарно публикуется без перезаписи: команды, одновременно работающие в одном `build_root`, используют один готовый файл для одинаковых переменных без конфликтов и блокировок. При ошибке записи временный файл удаляется; сбой удаления сообщается отдельно. Пустые созданные каталоги могут остаться. Успешный файл принадлежит вызывающей операции и живёт до её очистки; уничтожение значения его не удаляет. Вызов синхронный: из корутины используйте блокирующий executor. Каталог сборки должен находиться под контролем вызывающего кода.
