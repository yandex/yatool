### Что это и зачем

Быстрый потоковый json. Содержит минимум функциональности и заточен под загрузку и выгрузку сборочных графов.
В отличие от других библиотек, читает и пишет файл по частям, поэтому потребляет мало памяти.
Оптимально сочетается с UCompressor (devtools/ya/exts/compress.py), хотя с несжатыми файлами тоже работает хорошо, но там все преимущества теряются на фоне задержек ввода-вывода.

Работает только с байтовыми потоками, поэтому файл надо открывать как двоичный:
```
    from devtools.ya.yalibrary import sjson

    with open("dest.json", "wb") as f:
        sjson.dump(data, f)
    with open("dest.json", "rb") as f:
        sjson.load(f)
```

dumps() и loads() реализованы как запись и чтение промежуточного io.BytesIO и подходят больше для тестов, чем для практического применения.

Особенности dump:
  - не проверяет и не вызывает `__json__`.
  - не умеет в форматирование, отступы и прочие красивости, типа сортировки ключей.
  - нет опции ensure ascii. Всё, кроме спецсимволов, выводится как есть - в utf8.
  - строки не проверяются на валидность utf8.
  - имеет защиту от циклических ссылок внутри данных.
  - специально для формирования автосборочных контекстов поддерживает функцию в качестве значения. Такая функция вызывается с выходным потоком в качестве аргумента.
  - передаёт данные в `stream.write()` порциями не больше 64 KiB, в том числе при записи больших строк.

### Загрузка только нужных полей

`load()` и `loads()` поддерживают проекцию объектов внутри выбранного массива:

```python
    data = sjson.load(
        source,
        array_item_path=('graph', 'graph'),
        array_item_key_white_list=('uid', 'deps', 'inputs', 'outputs', 'kv'),
    )
```

В этом примере у нод массива `data['graph']['graph']` сохраняются только перечисленные поля.
Остальные поля нод, например `cmds`, пропускаются SAX-парсером без создания Python-объектов для их значений.
Содержимое сохранённых полей и остальные части документа загружаются как обычно.
Результат состоит из обычных Python `dict` и `list`, а не ленивых объектов.

Особенности проекции:
  - путь задаётся последовательностью ключей объектов; пустой путь выбирает корневой массив.
  - фильтруются непосредственные поля объектов — элементов выбранного массива, а не одноимённые поля на любой глубине.
  - вместе с `array_item_path` требуется непустой `array_item_key_white_list`; список без пути тоже недопустим.
  - можно сочетать с существующими `root_key_white_list` / `root_key_black_list` и интернированием строк.
  - пропущенные значения не материализуются, но их JSON-синтаксис проверяется: проекция не скрывает повреждённый документ.

Проекция уменьшает размер загруженного результата, но сам результат целиком остаётся в памяти.

### Компактные изменяемые контейнеры

Опция `compact_paths` у `load()`, `loads()` и `load_file()` позволяет хранить выбранные
поддеревья в `CompactMap` / `CompactList`: плотном C++-хранилище с Python-представлениями
и отдельным слоем изменений. Без этой опции возвращаются обычные `dict` / `list`.

[Описание compact-хранилища](COMPACT.md): назначение, устройство и дедупликация,
инварианты, владение памятью, мутабельность, примеры, ограничения совместимости,
ширина индексов и диагностика памяти.
Там же приведены ответственность классов и таблица потребителей: BuildPlan/runner,
resolver/packaging, JSONL, native AC, диагностика и потоковая отправка `DiskGraph`.
[Отчёт о покрытии](COVERAGE.md) содержит Python/Cython/clang-измерения, покрытие diff
и явные исключения для непокрытых путей.

### Прямое чтение JSON и UC из файла

`load_file(path, **options)` принимает путь к файлу и те же опции, что `load()`:

```python
    data = sjson.load_file(
        'context.json.uc',
        array_item_path=('graph', 'graph'),
        array_item_key_white_list=('uid', 'deps'),
    )
```

Файл читается непосредственно в C++. Если имя заканчивается на `.uc`, используется native UC decoder.
Промежуточный Python-поток, pipe и Python bytes для распакованных блоков не создаются.
При чтении и распаковке освобождается GIL; перед Python callbacks он восстанавливается, также проверяются сигналы.
Временная распакованная копия файла не нужна, исходный файл не изменяется.

Поддержан обычный JSON и UC с заголовком, совместимым с `library/cpp/ucompress`.
Для legacy UC, например без заголовка, остаётся прежний путь через `exts.decompress.udopen` и `sjson.load()`.
Сам `load_file()` автоматически на Python decoder не переключается.

### Потоковое переписывание JSON

`rewrite_object(stream, output, root_key=None, replacements=None)` копирует JSON-объект в двоичный выходной поток,
при необходимости извлекая объект из корневого поля и заменяя его непосредственные поля:

```python
    with open('context.json', 'rb') as source, open('graph.json', 'wb') as output:
        sjson.rewrite_object(
            source,
            output,
            root_key='graph',
            replacements={'conf': new_conf, 'result': result_uids},
        )
```

В `graph.json` записывается сам объект `graph`, без внешнего контекста.
При `root_key=None` переписывается весь корневой объект.
`rewrite_file(path, output, root_key=None, replacements=None)` делает то же самое с прямым native-чтением JSON/UC:

```python
    with open('graph.json', 'wb') as output:
        sjson.rewrite_file(
            'context.json.uc',
            output,
            root_key='graph',
            replacements={'conf': new_conf, 'result': result_uids},
        )
```

Особенности переписывания:
  - неизменяемые части документа разбираются и записываются без построения полного дерева Python-объектов.
  - `replacements` задаёт замену непосредственных полей выбранного объекта, а не рекурсивное слияние. Отсутствующие поля добавляются.
  - значения замен сериализуются прямо в выходной поток, без предварительного `dumps()` и промежуточного JSON-буфера всей замены.
  - неизвестные поля выбранного объекта сохраняются; форматирование и побайтовое совпадение исходного JSON не гарантируются.
  - корневой выбранный элемент должен быть объектом: массив, `null`, отсутствие нужного поля или некорректный JSON приводят к ошибке.
  - `root_key` и ключи замен могут быть строками или bytes; Python-обёртка нормализует их в bytes. Native API заранее проверяет типы и возвращает `TypeError` при нарушении контракта.
  - записи в `output.write()` ограничены 64 KiB. Это ограничение порции вывода, а не памяти крупнейшей JSON-строки или переданных Python-значений замен.
  - исходный файл не изменяется; его можно повторно прочитать для следующей попытки сериализации. Входной и выходной файл должны быть разными.
  - запись не атомарна: при ошибке входа или выхода результат может остаться частичным. Ошибки Python-потоков передаются вызывающему коду.

Для `rewrite_file()` действуют те же ограничения UC-формата, что для `load_file()`.
Для legacy UC можно передать поток из `udopen` в `rewrite_object()`.

### Замечания по реализации:

1. Не используются TJsonWriter (library/cpp/json) и IOutputStream-абстракции, потому что на них суммарно теряется 20 и более процентов производительности.
2. Вывод напрямую в файл, минуя Python-машинерию, особого преимущества не показал - разница составила единицы процентов.
