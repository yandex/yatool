# Введение
Описание тулов (инструментов) хранятся в файле build/ya.conf.json. Подробная документация с описанием формата файла и терминологией вокруг него находится по [ссылке](https://docs.yandex-team.ru/ya-make/extension/ya_conf_json).

# Именование платформ

Во флагах `--host platform`  и `--target-platform`) нужно указывать, либо полное имя платформы `clang20-linux-x86_64` или `default-linux-x86_64`, либо только OS (`linux`), тогда полное имя платформы будет "угадано" - подставлено `default-` в начале, и архитектура хоста в конце (см. функцию [guess_platform()](https://a.yandex-team.ru/arcadia/devtools/ya/yalibrary/platform_matcher/matcher.pyx?rev=r20376273#L218)). Хотя официальной терминологии на этот счёт нет, будем называть такой формат имени **полным**. Что такое `default-` и откуда он берётся, будет описано отдельно.

В опции `--host-platform` для `ya tool` нужно указывать, либо только операционную систему, либо операционную систему и архитектуру через дефис (примеры: `linux` или `linux-aarch64`). Назовём такой формат **сокращённым**.

В коде ya-bin есть несколько представлений платформ: как в виде строки, так и виде словарей, причём видов словарей несколько.

Есть разброд и шатание в регистре названий:
- в файле ya.conf.json в секции toolchain, операционная система указывается в верхнем регистре (`LINUX`), а архитектура - в нижнем (`arm64`)
- в коде ya-bin полное название платформы, если в виде строки, то имеет верхний регистр, а если в виде структуры [ToolInfo](https://a.yandex-team.ru/arcadia/devtools/ya/yalibrary/tools/__init__.py?rev=r20376273#L249), то OS - в верхнем, а всё остальное - в нижем.
- сокращённое название и в файле ya.conf.json, и в коде имеет нижний регистр.
- сокращённое и полное название платформы по функциям не пересекаются, например, в [platform_matcher/matcher.pyx](https://a.yandex-team.ru/arcadia/devtools/ya/yalibrary/platform_matcher/matcher.pyx?rev=r20376273#L180) есть два комплекта функций для получения текущий платформы и сравнения платформ между собой.

И вишенка на торте: платформа тула указывается дважды: в тулчейне и в bottle.formula. Первое участвует в сортировке тулчейнов для выбора наиболее подходящего, второе - описывает физическую возможность скачать тул под указанную платформу.

Систематическое описание всего спектра функций и видов представление платформ в коде и вокруг него в этом документе отсутствует - только подсвечена проблема.

# Функции модуля
Тулчейн (toolchain) - это набор из одного или нескольких тулов. По запросу архив тулчейна привозится из Sandbox или S3 и распаковывается в специальный каталог. Путь к распакованному архиву будем называть "путь к тулчейну".

## tools, tool, param, environ, toolchain_root, resource_id

Функции `tools`, `param`, `environ` обслуживают только хендлер `ya tool`:
- `tools` - возвращает список всех имеющихся тулов
- `param` - находит тул по имени и из словаря `params` его тулчейна (секция `toolchain.<toolchain>.params`  в `ya.conf.json` ) возвращает значение для переданного ключа. Значение отдаётся в "сыром" виде - раскрытие переменных `$(...)` не производится.
- `environ` - возвращает содержимое секции `environ` тулчейна из описания в `ya.conf.json`. Если в секции `params` тулчейна есть параметр `match_root`, то переменные `$(<match_root value>)` заменяются на путь к тулчейну. Примечание: в самом хендлере `ya tool` производится ещё одна подстановка: переменная `$(ROOT)` также заменяется на путь к тулчейну.

Следующие функции используются и за пределами `ya tool`:
- `toolchain_root()` - возвращает путь к тулчейну.
- `tool()` - возвращает, либо только путь к исполняемому файлу тула (`with_params=False`), либо tuple из двух элементов - путь к исполняемому файлу и словарь `params` тулчейна (`with_params=True`). В режиме `with_params=True` к словарю дополнительно добавляются ключи: `toolchain_root_path` (путь к тулчейну), `toolchain` (имя тулчейна), и `toolchain_name` (имя исполняемого файла в верхнем регистре, если задан).
- `resource_id` - возвращает Sandbox resource id ресурса, в котором хранится архив тулчейна для заданного тула и платформы.

{% note info %}

Функции `toolchain_root()`, `tool()` и `environ()` привозят и устанавливают тул.

Функция `resource_id()` для автообновляемых тулов может инициировать поход в Sandbox API.

{% endnote %}



Тул с одним и тем же именем может присутствовать одновременно в нескольких тулчейнах (например, несколько вариантов компилятора `c++` под разные платформы), поэтому встаёт задача поиска самого подходящего. Во всех перечисленных выше функциях это делается путём предварительной сортировки тулчейнов (см. [`_Toolchain.__init__`](https://a.yandex-team.ru/arcadia/devtools/ya/yalibrary/tools/__init__.py?rev=r20376273#L126)). При поиске тула просматриваются все тулчейны в этом сортированном списке, и тул берётся из первого, в котором этот тул существует. Порядок сортировки тулчейнов следующий:
1. тулчейны, явно переданные пользователем в параметре `extra_toolchain`
2. тулчейны, у которых в одной из платформ хостовая ОС (`host.os`) и таргетная ОС (`target.os`) совпадает с ОС, на которой запущен ya). Если таргетная ОС в платформе отсутствует, то считается, что она совпадает с хостовой.
3. тулчейны, у которых совпадает только хостовая ОС.
4. все остальные тулчейны

## `iter_tools`
`iter_tools`  возращает итератор по тулчейнам (тип элементов [ToolInfo](https://a.yandex-team.ru/arcadia/devtools/ya/yalibrary/tools/__init__.py?rev=r20376273#L249)), которые содержат тул с заданным именем. Итерация происходит не только по тулчейнам, но и по платформам внутри тулчейна, поэтому тулчейн возвращается столько раз, сколько у него платформ, но если у платформы установлен атрибут `default=true`, то для одной платформы итератор выдаёт не один элемента, а два: один - с именем платформы `{toolchain}-{os}-{arch}`, а второй - с `default-{os}-{arch}`.  Для `params` и `env` тулчейна производится особая подстановка переменных (см. в документации [params](https://docs.yandex-team.ru/ya-make/extension/ya_conf_json#params) и [env](https://docs.yandex-team.ru/ya-make/extension/ya_conf_json#env)).
Порядок тулчейнов, в котором их отдаёт итератор, строго говоря, не определён, но из-за свойств dict в Python 3, он будет совпадать с порядком тулчейнов в `ya.conf.json`, но закладываться на это нельзя.

Пример результата функции для тула `c++`:
```
Y_PYTHON_ENTRY_POINT=:main ya -c 'from yalibrary import tools; import json; [print(json.dumps(x, indent=4)) for x in tools.iter_tools("c++")]'
```

## `resolve_tool`
Функция использует `iter_tools` для получения списка тулчейнов, и возвращает первый элемент из последовательности, который удовлетворяет переданным в аргументах `resolve_tool()` именам хостовой и таргетной платформ. Имя  платформы должно быть указано в полном формате.
Функция имеет два режим работы:
- если параметр `toolchain_key` не указан, то хостовая и таргетная платформы искомого тулчейна должны полностью, включая имя тулчейна, совпадать с переданными в аргументах.
- если параметр `toolchain_key` задан, то, во-первых ищется ищется только тулчейн с указанным в этом параметре именем, а, во-вторых, сравниваются только os и arch тулчейна. Подробнее о том, зачем он существует, можно посмотреть в [Pull Request](https://a.yandex-team.ru/review/13494827/details), где он был добавлен.
