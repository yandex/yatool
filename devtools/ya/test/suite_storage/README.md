# Mutable storage тестовых сьютов

Общий scoped API и backend-библиотеки описаны в [`base/README.md`](base/README.md).
`in_memory` хранит новые модели в памяти; `disk` хранит изменяемые snapshots
и метаданные на диске. Выборки `Suites` разделяют ссылки на одни записи.

## Доступ к моделям

`read()` и const-итераторы позволяют читать модели без сериализации и write-back.
Редактирование выполняется через `edit()`. Для передачи данных за пределы scope
нужно создать самостоятельные plain-контейнеры, например через `deepcopy()`.

## Потоковая загрузка custom context

`loading.SuiteCollector` принимает записи из callback потокового JSON-парсера.
Каждая запись `tests` или `stripped_tests` передаётся в callback:

```python
collector.consume(('tests',), uid, serialized_suite)
```

Строка pickle в latin-1 сохраняется в mutable disk backend. Для построения
SQLite-индекса восстанавливается одна временная модель, освобождаемая до следующей
записи. Все pickle-строки не накапливаются в DOM. Повторный UID сохраняет последние
байты и позицию первого появления, как обычный dict.

`finish_loading()` завершает наполнение. Ошибка вставки делает collector
непригодным к финализации. Владелец закрывает оба storage и временную директорию
при ошибке парсинга или индексирования. Вызывающий код отвечает за lifetime
collector и заимствованных моделей после успешной загрузки.

`Suites.from_serialized()` принимает уже materialized dictionaries и сохраняет
ленивый импорт. При потоковой загрузке остаётся память для крупнейшего pickle
и одной временной модели; остальные поля JSON обрабатывает вызывающий код.
